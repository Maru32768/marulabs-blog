# 日本語検索の品質検証

検証日: 2026-11-07 / Pagefind 1.6.0 / `tests/fixtures/articles` の12記事（日英混在）

主要なクエリは `tests/e2e/search.spec.ts` で回帰テストにしています。

## 構成

- 全ページ `<html lang="ja">`。Pagefind は言語ごとに索引を分けるため、日英混在でも1つの索引にまとまります。
- npm の `pagefind` は extended 版を使い、日本語の分かち書きのない文を単語に分割します。
- 語形変化の吸収（ステミング）は日本語では行われません。英語も `ja` 索引の中では行われません。

## 分かっている制限

| 事象                                       | 例                                    | 影響と対応                                           |
| ------------------------------------------ | ------------------------------------- | ---------------------------------------------------- |
| 半角カナ・全角英字を正規化しない           | `ﾄﾗﾝｻﾞｸｼｮﾝ` `Ｖａｃｕｕｍ` → 0件      | 実害は小さいので対応しない                           |
| ひらがな読みで引けない                     | `とらんざくしょん` → 0件              | 読み情報を持たないため。対応しない                   |
| 語形変化を吸収しない                       | `replication` と `replicate` は別の語 | 記事の語彙に合わせて検索する必要がある               |
| 活用語は分割されて範囲が広がる             | `書き込む` → 5件（`書き込み` は3件）  | 上位は妥当。許容する                                 |
| 存在しない語が部分一致で無関係な記事を返す | `canary` `フィンガープリント` → 1件   | 適合率がやや下がる。許容する                         |
| タグは本文として索引しない                 | タグのみの語 `replication` → 0件      | タグはフィルタで絞り込む。本文に語があればヒットする |

自前の検索サーバーや形態素解析を足すほどの問題はないと判断しました。記事が増えて問題になったら、ここに記録したクエリで再評価します。

## 公開境界

`pagefind-fragment` はビルド後に `scripts/verify-dist.ts` が展開し、索引された URL が公開記事の slug と完全に一致することを確認しています。一覧ページや About は索引に入りません。
